# AI 연동 3안
기존 AI 기반을 실제 서비스로 연결하는 3차 계획
상태: 3차 계획 · 미구현 항목 포함

## GPT를 붙이기 전, 계약부터.
호출 코드는 이미 있다.3차 목표는 실제 사용자 흐름·답변 품질·비용·실패 처리를 연결하는 것이다.

입력·동의 → 접수·작업 → Responses → 결과 검증 → 표시·기록

| 이미 있는 기반 | 3차에서 할 일 |
| --- | --- |
| Responses adapter·strict 결과 스키마 | 모델·prompt·거절·미완료 실호출 확인 |
| 작업 큐·멱등·취소·재시도 | 늦은 결과·불확실한 호출의 사용자 안내 |
| 소유권·동의·참고 기록 version | 계정 전환·동의 철회·기록 변경 경계 검증 |
| 기본/AI 별도 전송 경로 | 입력창에서 전송 책임·표시 흐름 정리 |
| 3장 AI 결과 계약 | 1/3/5장 지원 범위 확정·필요 계약 변경 |

실제 GPT 응답을 이번 영상에서 시연하지 않는다. AI 화면·흐름은 계획 설명이다. 모델 이름·요금·응답시간 목표는 사용 사례 평가 후 확정한다.

## 기능별로 AI의 역할을 제한한다.
카드 선택과 사용자 결정을 AI에게 넘기지 않는다.

| 순서 | 기능 | 성공 기준 |
| --- | --- | --- |
| 3-1 | 카드·대화 계약 | 기본/AI·1/3/5장 입력과 결과 정합성 |
| 3-2 | 타로 해석 | 확정 카드 ID·방향·순서 보존 |
| 3-3 | 상담·이어가기 | 최근 문맥 유지·구체적 조언·말투 일관 |
| 3-4 | 마음기록 요약 | 선택한 본인 기록만 참고 |
| 3-5 | 음성 전사 | 사용자 확인·수정 뒤 별도 전송 |
| 3-6 | 운영·품질 | 실패·사용량·비용·지연 관찰 |

말투는 다정하게·기가차드 모드를 유지한다. 기가차드는 짧고 단호한 응원이며 비난·모욕·강요를 뜻하지 않는다. 표정은 calm·welcome·listen·encourage·joy·concern·serious 범위에서 선택한다.

## 데이터는 앱의 서버가 검증한다.
프론트가 OpenAI를 직접 호출하지 않고, 도메인과 외부 HTTP adapter를 분리한다.

RN·React → FastAPI 유스케이스 → DB 작업 → AI 작업자 → OpenAI

```
{
  kind: "tarot | chat | insight",
  empathy, summary, advice,
  actions: ["1~3개 작은 행동"],
  expression: "허용된 표정",
  card_insights: [{card_id, position, meaning, reflection}],
  follow_up_questions: []
}
```

위는 현재 결과 필드를 설명하는 개념 표기이며 그대로 전송하는 JSON이 아니다. strict JSON schema 뒤에도 카드 계약·문구·권한을 서버가 검사한다. 거절·토큰 부족·미완료 응답은 성공 결과로 표시하지 않는다.

기존 store:false 설정을 유지하되 이를 모든 보관·로그가 없다는 의미로 설명하지 않는다. 앱의 동의·삭제·로그 정책을 별도로 정의한다.

## 비용·재시도·품질을 함께 본다.
현재 설정값과 앞으로 확정할 운영 정책을 구분한다.

| 현재 정책 파일 값 | 의미 |
| --- | --- |
| 사용자20 / 전역200회·일 | 실제 요금제나 금액 예산 확정 아님 |
| 동시 작업1·deadline60초 | 대기·취소·장시간 처리 안내 필요 |
| 최대 출력1500tokens | 모델·입력 길이별 실제 비용 평가 필요 |
| 최근6turns·참고 기록3개 | 문맥 크기 제한·선택 자료 범위 검증 |
| 음성60초·10MiB | 전사 전 사용자 확인·임시 파일 정리 |

| 평가 묶음 | 반드시 볼 케이스 |
| --- | --- |
| 계약 | 타인 자료·동의 철회·기록 version 변경 |
| 일관성 | 카드 ID/장수·이전 대화·말투·표정 |
| 실패 | 거절·미완료·429·통신 결과 불확실 |
| 품질 | 공감·구체적 조언·선택 가능한 작은 행동 |

## 출시까지의 실행 순서.
실제 구현 전에 완료 기준을 고정하고, 변경마다 문서와 안내 영상을 갱신한다.

동선 명세 → API·스키마 → 기능 연결 → 제한된 평가 → 배포·관찰

| 단계 | 완료 조건 |
| --- | --- |
| 입력창 | 주 버튼 열기·키보드·초안·중복 전송 조건 정의 |
| AI 기능 | 타로 → 상담 → 기록 요약 → 음성 순으로 연결 |
| 검증 | 중복·동의·소유권·카드·실패 후 입력 보존 |
| 평가 | 실제 모델 호출량·예산 한도 정한 뒤 품질·지연 측정 |
| 배포 | 서버·JS·네이티브 호환성·복구 확인 |
| 사용 안내 | 준비 상태를 실제 기능 상태로 갱신 후 재촬영 |

참고: OpenAI 공식 Structured Outputs 및 Responses 문서를 대조했다. 구조화된 형식은 답변 의미의 정확성을 보증하지 않는다. 최신 모델·가격은 실제 선택 시 다시 확인한다.

공식 근거: developers.openai.com/api/docs/guides/structured-outputs ; developers.openai.com/api/docs/guides/migrate-to-responses
